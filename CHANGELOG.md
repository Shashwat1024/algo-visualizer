# Changelog

All notable changes to this project are documented here, newest first. Format loosely follows [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased]

### Added
- **Phase 6 — Generic animation engine** (2026-08-01): the visualizer is no longer sorting-only. The tracer now snapshots every visualizable local per frame and assigns each a role by inspecting the values it actually held — dict-of-lists or square 0/1 matrix → `graph`, objects with `left`/`right`/`children` → `tree`, `deque` or head-removal → `queue`, tail-pop → `stack`, numeric list → `array`. This is the runtime replacement for the dropped LLM classification step. Stack/queue/array cannot be told apart from a value alone, so they are separated by mutation pattern across frames; append-only lists count as accumulating results rather than stacks. Added `GraphRenderer` (d3-force), `TreeRenderer` (d3-hierarchy), and `SequenceRenderer` alongside the existing bars, dispatched by role, with sets (`visited`) and scalars driving highlight state. Layouts are computed once from the whole trace so scrubbing never reshuffles them, and aliases of the same graph or subtrees of the same root are deduped into one panel. The tracer now also traces module-level code, so graph/tree examples can build their own input and call themselves; a bare sorting function with no call still gets invoked with a random array as before. Added BFS, DFS, and tree traversal examples. Regression-checked: all five sorting examples still trace and sort correctly.

### Removed
- **Dropped the planned LLM classification phase** (2026-08-01): the original plan had a Phase 6 that POSTed pasted code to `app/api/classify/route.ts` and used Claude with structured output to tag each variable's data-structure role. Removed by decision — the same roles can be derived by inspecting values at runtime in the tracer, which is deterministic, free, offline, and keeps the app fully client-side with no API routes, no API key, and no server dependency. Structure detection moves into the generic animation engine, and the remaining phases renumber to 6 (Generic Animation Engine) and 7 (Polish).

### Added
- **Phase 5 — Arbitrary user-submitted code** (2026-08-01): replaced the fixed algorithm dropdown with a CodeMirror editor (Python syntax, theme-aware) so any pasted sorting function can be traced. The tracer no longer assumes a variable name — it snapshots every number-list local per frame and picks the "primary array" by scoring candidates on whether they end fully sorted, with amount of movement as the tiebreak. That first term matters: without it, an algorithm that builds a new list loses to the untouched input it was derived from. Added a 20,000-step limit so infinite loops fail in ~0.07s with a clear message rather than hanging, plus surfaced syntax errors, missing functions, and bad signatures as readable errors. Examples dropdown now loads starter snippets (bubble/insertion/selection/quick/merge) into the editor instead of gating what can run, and input size is selectable (8–32). Validated against five sorts never written for this project — including a non-in-place merge sort and gnome sort — all ending correctly sorted.
- **shadcn/ui component system + dark/light mode** (2026-08-01): initialized shadcn/ui (Base UI primitives, Tailwind v4, `new-york` style) and rebuilt the interface around `Card`, `Button`, `Select`, `Slider`, `Badge`, and `Separator` instead of hand-rolled markup. Added a sticky header with a `next-themes` light/dark toggle (defaults to dark, follows system). Playback controls now use icon buttons and a real slider; the visualization surfaces the current frame's line number, recursion depth, and swap state. Introduced `--bar` / `--bar-compare` theme tokens so bar highlighting is legible in both themes rather than hardcoded zinc/amber.

### Changed
- **Mono font swapped to JetBrains Mono** (2026-08-01): replaced Geist Mono with JetBrains Mono (via `next/font/google`) as the project's `--font-mono`, used by the code preview/editor areas.

### Added
- **Phase 4 — Merge sort, quick sort, recursion depth** (2026-08-01): reference merge sort and quick sort implementations added alongside bubble sort, all through the same `sys.settrace` tracer. Recursion depth is now captured per frame via `'call'`/`'return'` events (not yet rendered, but cheap to capture now vs. retrofit later). Algorithm dropdown replaces the free-text editor for this phase — code preview is read-only, reflecting PLAN.md's "still hardcoded" scope; free-text user code lands in Phase 5. Validated the tracer module standalone against CPython (all three algorithms sort correctly; merge sort reaches depth 5, quick sort depth 6 on a 12-element input) before relying on the in-browser Pyodide run.
- **Phase 3 — Bubble sort tracer & visualization** (2026-08-01): hardcoded bubble sort run through `sys.settrace` inside the Pyodide worker, emitting `{line, arrayState, comparedIndices, swapped}` per frame (swap detection via array diffing between consecutive line events, no manual tagging). `BarsVisualizer` renders the current frame with compare highlighting. `PlaybackControls` adds play/pause, step forward/back, scrub slider, and speed selection over the captured frame list.
- **Phase 2 — Pyodide Web Worker spike** (2026-08-01): `public/pyodide-worker.js`, a module Web Worker that loads Pyodide (v0.28.3) and confirmed `sys.settrace` fires correctly with accurate line numbers and locals inside the worker sandbox — de-risking the core tracing approach the whole project depends on.
- **Phase 1 — Project scaffolding** (2026-08-01): Next.js App Router shell (TypeScript, Tailwind, ESLint) via `create-next-app`; page shell with code textarea, Run button, visualization area; GitHub repo created and pushed ([Shashwat1024/algo-visualizer](https://github.com/Shashwat1024/algo-visualizer)); Vercel project linked and deployed to production.
